How to choose a fraud detection threshold by cost

A fraud model outputs a probability. Turning it into a yes-or-no alert is a business decision, and the default 0.5 is almost never right.

Start with what each mistake costs

  • Missed fraud (false negative): you lose the transaction amount and pay a chargeback fee. This project uses amount + $15.
  • Alert (true or false positive): an analyst spends time reviewing it. This project uses $5.
  • False alarm friction: optionally, the cost of annoying a good customer. Set to $0 here, but worth adding if you block payments rather than review them.

Option 1: the cheapest single threshold

Score the validation period, try every cut-off from 0 to 1, add up the cost at each, and keep the cheapest. On IEEE-CIS this landed at 0.014, far below 0.5, because missing an average $150 fraud is about 30 times more expensive than a review. On the test month it cost $172,751 against $409,060 for the 0.5 cut-off. You can try this yourself in the threshold calculator.

Option 2: the expected-loss rule

A single threshold treats a $5 purchase and a $5,000 purchase the same. The expected-loss rule alerts when the expected cost of letting the transaction through is higher than the cost of reviewing it:

alert if  p × (amount + chargeback)  >  review cost + (1 − p) × friction

With a $5 review and $15 chargeback, a $10 order needs a fraud probability above 20% to be reviewed, while a $1,000 order needs only 0.5%. On the IEEE-CIS test month this rule cost $138,481, 20% less than the best single threshold, with roughly half the alerts.

Two things that make it work

  1. Calibrated probabilities. The rule multiplies the probability by dollars, so the probability has to mean what it says. Avoid heavy class reweighting, or recalibrate afterwards.
  2. Choose on validation, report on test. On the small ULB set, the best validation threshold did worse on test than the 0.5 cut-off. Pick the policy by validation cost and accept the test result, rather than tuning to the test set.

When to revisit the threshold

Recompute when costs change (a new chargeback fee, more analysts), when the fraud rate moves, or when a drift check fires. This project's drift job compares feature distributions and the mean score with a training reference, using the population stability index.

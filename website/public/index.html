Fraud detection that minimises cost, not just errors

An end-to-end machine learning system trained on two real, labelled transaction datasets. It picks who to alert by the dollars at risk, explains every alert, and ships with a scoring API, an analyst queue, CI and drift monitoring.

What this project does

Card and e-commerce fraud is rare (3.5% of transactions in IEEE-CIS, 0.17% in the ULB card data), so a model that predicts "not fraud" for everything is over 96% accurate and catches nothing. This project treats fraud detection as a cost problem instead. A missed fraud costs the transaction amount plus a $15 chargeback fee, and every alert costs $5 of analyst time. The model scores each transaction, and the system alerts only when the expected loss is larger than the cost of reviewing it.

Everything is evaluated out of time: the model trains on earlier months, is tuned on the next month and is reported on a final month it has never seen, which is how fraud models actually meet new data in production.

Built like a production system

  • Two real datasets: IEEE-CIS (590,540 Vesta e-commerce transactions) and ULB (284,807 European card transactions).
  • Models: LightGBM against a logistic regression baseline, with train, validation and test metrics to expose overfitting.
  • Decisions: an amount-aware expected-loss rule that beat every single fixed threshold on both datasets.
  • Explanations: the top three reasons for every alert, from SHAP values.
  • Serving: a FastAPI /score endpoint and a Streamlit alert queue for analysts.
  • Operations: Docker, GitHub Actions CI, a model registry file per run and a PSI drift check.
